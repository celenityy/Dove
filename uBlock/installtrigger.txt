! Title: InstallTrigger Stub
! Version: 26June2025v1
! Expires: 12 hours
! Homepage: https://dove.celenity.dev

!! For context, we disable the mozAddonManager API, due to privacy (fingerprinting) and security (added attack surface) concerns. It also prevents extensions (like uBlock Origin) from being able to access ATN (addons.thunderbird.net), and bypasses the permission prompt to install add-ons.
!! https://bugzilla.mozilla.org/show_bug.cgi?id=1952390#c4
!! https://bugzilla.mozilla.org/show_bug.cgi?id=1384330

!! When mozAddonManager is disabled on Firefox, AMO will fallback and successfully install add-ons without fail out of the box. This is unfortunately NOT the case for ATN currently.
!! https://github.com/thunderbird/addons-server/issues/332

!! HOWEVER, ATN DOES still have a fallback when mozAddonManager is disabled, via the legacy InstallTrigger interface (which is disabled by default nowadays, via the `extensions.InstallTriggerImpl.enabled` pref).
!! https://devdoc.net/web/developer.mozilla.org/en-US/docs/XPInstall_API_Reference/InstallTrigger_Object.html
!! https://searchfox.org/mozilla-central/source/dom/webidl/InstallTrigger.webidl

!! So essentially, what we're doing is disabling mozAddonManager, re-enabling InstallTrigger with that pref so ATN can fall back, and setting the InstallTrigger interface to return `null` for every website EXCEPT ATN, to avoid fingerprinting.
!! Additionally, for ATN, we're also going to stub `window.InstallTrigger.enabled` and `window.InstallTrigger.updateEnabled`, to prevent exposing whether the user has enabled or disabled the installation of add-ons (via the `xpinstall.enabled` pref).

!! This effectively allows users to install add-ons from ATN, but without compromising their privacy and security.

*##+js(set, window.InstallTrigger, null)

addons.thunderbird.net#@#+js(set, window.InstallTrigger, null)
addons.thunderbird.net##+js(set, window.InstallTrigger.enabled, null)
addons.thunderbird.net##+js(set, window.InstallTrigger.updateEnabled, null)
